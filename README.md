# FOOD CHAIN — SibGameJam Autumn

Короткий first-person CCTV-хоррор: наблюдение, заметки, угрозы в квартире и финальный тест.
Все наблюдаемые люди и события вымышлены.

## Запуск

1. Установить **Godot 4.6.2 standard**, не .NET — найденная локальная версия из ветки 4.6.
   Используем одинаковую версию и export templates; обновления согласовываем вместе.
2. Клонировать репозиторий или выполнить `git pull --ff-only` в чистой рабочей копии.
3. Импортировать `project.godot`, дождаться импорта ресурсов.
4. Нажать **F5**. **F6** запускает открытую сцену `scenes/main.tscn`.

Сейчас доступен первый блокинг: комната героя, личный санузел, спальня и общий
коридор со щитком. Можно ходить, бегать и садиться за ПК с плавным переходом камеры
к полноэкранному интерфейсу. На ПК пока заглушка — CCTV и игрового цикла ещё нет.
Рендер — **Compatibility**, базовое окно — **1280×720**, масштабирование — `canvas_items`.
Локальная `icon.svg` намеренно не отслеживается; проект не зависит от неё.

## Структура

| Путь | Назначение |
| --- | --- |
| `scenes/main.tscn` | Композиция квартиры, игрока, ПК и интерфейсов |
| `scenes/apartment/`, `player/`, `terminal/`, `ui/` | Независимые редактируемые сцены подсистем |
| `scripts/` | GDScript с таким же разделением по подсистемам |
| `data/` | Будущие ресурсы таймлайна, камер и вопросов, отдельно от представления |
| `assets/` | Модели, текстуры, материалы, звук, шрифты и графика UI |
| `doc/` | Концепт и бэклог |
| `build/` | Локальные экспорты, исключены из Git; `.gdignore` исключает их из импорта Godot |
| `default_bus_layout.tres` | `Master`, `Ambience`, `SFX`, `Voice` |
| `tests/prototype_smoke.gd` | Desktop-проверка коллизий, движения и 10 циклов ПК |
| `tools/` | Необязательные инструменты разработки; не входят в экспорт |

Подпапки подсистем создаём по мере реализации, без пустых менеджеров и скриптов.
Имена ресурсов — `snake_case`; ноды — `PascalCase`.

## Ближайший прототип

Следом: две камеры, независимый таймлайн, заметки, три вопроса, одна угроза.
Текущий шаг — проверка масштаба помещений, управления и перехода к компьютеру,
а не финальный арт или завершённая игровая смена.

### Управление

- ЛКМ в игре — захватить мышь; при запуске она свободна.
- Физические WASD — ходить, Shift — бежать, мышь — осматриваться.
- Подойти к столу, навести прицел на монитор/стол, дождаться подсказки и нажать E.
- На ПК: Esc или кнопка «Встать» — вернуться на безопасную точку справа от стула.
- В комнате: Esc — освободить мышь. Потеря фокуса также освобождает её и останавливает движение.
- Web: после освобождения мыши действует защитная пауза до двух секунд перед новым
  захватом (ограничение браузера). При быстром выходе из ПК может понадобиться ЛКМ;
  подсказка на экране объясняет ожидание. Аудио пока отсутствует.

Проходы открытые, декоративные двери соседей закрыты. Щиток пока только ориентир:
отключений электричества и взаимодействия с ним нет. Прыжка, приседания и тела игрока нет.

Планировка, редактирование сцены и воспроизводимые проверки:
[прототип и тестирование](doc/PROTOTYPE_TESTS.md).

## Экспорт

Установить export templates **той же версии**, что редактор, через
**Editor → Manage Export Templates**. В **Project → Export** доступны:

- `Web` → `build/web/index.html`, без потоков и нативных расширений.
- `Windows Desktop` → `build/windows/food_chain.exe`, x86_64.

Перед экспортом создать нужные выходные папки. При доступном CLI:

```powershell
New-Item -ItemType Directory -Force build/web, build/windows
godot --headless --path . --export-release "Web" build/web/index.html
godot --headless --path . --export-release "Windows Desktop" build/windows/food_chain.exe
```

`godot` означает путь к установленному исполняемому файлу Godot 4.6.
Web-сборку открывать через HTTP, не через `file://`, например при установленном Python:

```powershell
python -m http.server 8000 --directory build/web
```

Открыть `http://localhost:8000` в Chromium/Firefox. Проверять размеры окна,
ввод, захват/освобождение мыши, звук и консоль браузера. Экспорт сам по себе не равен
проверке в браузере. Параметры пресетов — стартовые; успешность экспорта нужно проверить.

## Совместная работа

- Перед работой подтянуть изменения; задачи делать небольшими, независимыми коммитами.
- Два кодера заранее делят подсистемы. Не редактировать одну `.tscn` одновременно:
  квартира, игрок, терминал и UI будут отдельными сценами.
- Общие `project.godot`, `main.tscn`, Input Map и ресурсы данных менять по договорённости.
- Для параллельных задач предпочтительны ветки `feature/<краткое-имя>` и PR.
- После проверки: `git add <нужные пути>`, `git commit`, `git push` в свою ветку;
  интеграционные изменения в `main` — по договорённости. Не использовать force push.
- Коммитить `.gd`, `.uid`, `.tscn`, `.tres`, ассеты, `*.import` и `export_presets.cfg`.
  Не коммитить `.godot/`, сборки, пароли и локальные настройки редакторов.
- Для переноса и переименования ресурсов пользоваться FileSystem Godot, сохраняя ссылки.
- В отчёте по задаче указывать реально выполненные проверки и оставшиеся блокеры.

## Проверки основы — 2026-10-29

На Godot 4.6.2 / Windows выполнены без ошибок:
- Импорт редактором в headless-режиме и запуск главной сцены на 10 кадров.
- Обычный запуск с Compatibility/OpenGL на 30 кадров (не визуальная приёмка).
- Release-экспорт Web и Windows Desktop с установленными шаблонами 4.6.2.
- Импорт и headless-запуск чистой копии из Git index, без локальной иконки и кэша.
- `git diff --cached --check`.

**Не проверено:** запуск Web в браузере, запуск экспортированного Windows EXE,
интерактивный ввод/звук и полный игровой цикл (механик ещё нет).

Это историческая проверка исходной основы. Актуальные проверки игрового блокинга
перечислены в [doc/PROTOTYPE_TESTS.md](doc/PROTOTYPE_TESTS.md).
