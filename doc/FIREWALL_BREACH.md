# FIREWALL BREACH

Короткая **вымышленная** мини-игра внутри игрового ПК. Номера портов — только
подписи кнопок: нет сокетов, сетевых запросов, проверки реальных портов или управления
системным firewall. Никаких внешних сервисов или настоящих окон ОС.

## Правила

- ID `firewall_breach`, оба типа запуска, только за ПК. Вес 1, как у You Are An Idiot.
- Сетка 3×3, фиксированные номера/позиции. В начале случайно открыты **6** портов.
  Красный + «ОТКРЫТ», зелёный + «ЗАКРЫТ»: информация не зависит только от цвета.
- Клик переключает состояние порта, в том числе ошибочный клик открывает зелёный.
- Хакер выбирает один закрытый порт. Интервал постепенно сокращается с 1–2 с
  до 0,7–1,2 с. Длинный кадр не вызывает догоняющую пачку открытий.
- После закрытия последнего красного порта новые открытия отложены минимум на
  **0,7 с**. Таймер продолжает идти; защита не добавляет времени после дедлайна.
- При полностью зелёной сетке доступен **BLOCK CONNECTION**. Только эта кнопка
  подтверждает победу; сама по себе зелёная сетка победой не считается.
- Победа: **CONNECTION BLOCKED** на 1 секунду, затем обычный рабочий стол.
- Истечение **15 секунд**: мини-игра и все обычные окна приложений закрываются,
  включая свёрнутые. **Данные не стираются:** заметки, переписка, состояние
  калькулятора и сами экземпляры приложений сохраняются. Открыть их можно сразу.
- Приложения, панель задач и их клавиатурный ввод заблокированы. Нельзя закрыть,
  свернуть или перетащить мини-игру. **Esc позволяет встать**, F7 работает штатно.
  При возвращении ПК остаётся заблокирован до конца ивента.
- Во время ходьбы таймер/атаки идут дальше. Проигрыш также закрывает приложения,
  даже если игрок не за ПК. Маршрут CCTV не приостанавливается.
- Красная рамка медленно пульсирует, помехи только в декоративном заголовке.
  Цифры/хитбоксы не двигаются. Без строба и сирены; есть тихие щелчки кнопок.

Результаты `won` / `lost` передаются существующим
`AtmosphereDirector.event_finished(id, outcome)` и видны в dev-истории. Опрос,
dev-отмена, отключение атмосферы, watchdog и конец забега — техническая очистка,
**не проигрыш**: приложения в этих случаях не закрываются.

## Настройки и файлы

- `data/atmosphere/firewall_settings.tres` (`FirewallBreachConfig`): длительность,
  начальное число красных портов, ранние/поздние интервалы, защита BLOCK.
  Длительность ограничена 1–19 с; подтверждение победы всегда 1 с. Максимум — 20 с.
- `data/atmosphere/firewall_breach.tres`: вес выбора, enabled, контексты и типы запуска;
  watchdog 20 с. Реализован через обычный `AtmosphereEvent`.
- `data/atmosphere/default.tres`: общий пул и интервал попыток случайного выбора
  (40–70 подходящих секунд). Вес задаёт относительную вероятность, не отдельный таймер.
  Одноразовость и резервирование межсценовых событий по-прежнему действуют: маленький
  пул не гарантирует случайные события сверх зарезервированных переходов.
- `scripts/atmosphere/firewall_round.gd`: состояние головоломки без UI; поддерживает
  seed для воспроизведения тестов.
- `scripts/atmosphere/firewall_breach_view.gd`: масштабируемый UI без дополнительных
  viewport, новых текстур или полноэкранных тяжёлых шейдеров.
- `scripts/atmosphere/firewall_breach.gd`: связка модели, UI, результата и очистки.
- `TerminalDesktop.set_modal_overlay()` / `clear_modal_overlay()` — блокировка
  приложений с сохранением активного приложения. `close_all_windows()` использует
  обычное закрытие, а не пересоздание приложений или очистку сеанса.

## Проверка

F5 → Играть → сесть за ПК → удерживать F7 → **TriggerFirewallBreach**.
Также доступен ID в общем dev-селекторе. Forced-запуск обходит cooldown/резерв/
одноразовость, но не другой ивент, угрозу, питание, опрос или неподходящий контекст.

```
godot --headless --path . --script res://tests/firewall_smoke.gd
godot --path . --script res://tests/firewall_smoke.gd
```

Web: во временной копии назначить main `tests/firewall_input_fixture.tscn`, включить
`tests/*` в экспорт и выполнить release Web export:

```powershell
$env:FIREWALL_WEB_ROOT = '<каталог Web экспорта>'
$env:FIREWALL_WEB = '1'
node tools/chat_web_check.mjs
```

Общие model/lifecycle-проверки: main `tests/firewall_fixture.tscn`, runner
`THREAT_WEB_ROOT` / `THREAT_WEB=1`. JS-команды и ускорение времени существуют только
в тестовых сценах, исключённых из production.

### Проверено (Godot 4.6.2 Compatibility)

- `firewall_smoke`: headless, настоящее desktop-окно и Chrome/WebGL2 release — PASS.
  Проверены seed/случайный старт, переключения, интервалы, grace, дедлайн,
  лимит длительности, отсутствие догоняющих атак, реальный GUI, оба результата,
  сохранность экземпляров/данных, выход/возврат, маршрут, переход, случайный запуск,
  техническая отмена, опрос, конец забега и выгрузка.
- Chrome input fixture: RU/EN, реальные F7/dev-кнопка, клики портов/BLOCK,
  заблокированный ввод приложений, победа, проигрыш, повторное открытие Блокнота
  двойным кликом, Esc, возврат и ресайз 800×600 — PASS.
- Headless-регрессии: idiot, atmosphere, shift, threat, police, neighbor, outage,
  fairness, lifecycle, chat, desktop, power — PASS. Desktop: idiot, atmosphere,
  desktop — PASS. В части прежних headless-тестов остаются известные shutdown-
  предупреждения об аудиоресурсах; новые firewall-тесты завершились без них.
- Нативные скриншоты: `%LOCALAPPDATA%/Temp/opencode/firewall_{active,ready,won,lost}.png`.
  Browser runner: `chat_web_firewall_{active,small,won}_{ru,en}.png`.
- Firefox, слабое железо и субъективная сложность/уровень паники требуют приёмки.
