# Первый игровой блокинг

## Что сделано

- Комната 6×6 м: стол с CRT и стулом, за спиной сидящего — шкаф и вход в спальню.
- Спальня 6×3.6 м с кроватью; личный санузел 3×3.8 м с ванной и туалетом.
- Общий коридор 2.4×14 м, щиток на дальнем торце, две декоративные двери соседей.
- Все три прохода открыты, статические коллизии на стенах, полу, потолках и крупных предметах.
- Ходьба 2.5 м/с, бег 4.3 м/с, камера на высоте 1.6 м; значения доступны в инспекторе игрока.
- Луч взаимодействия длиной 2.2 м, подсказка только при наведении на стол или монитор.
- Переход камеры за 0.7 с через SeatView к MonitorView и полноэкранному UI.
- Выход по Esc/кнопке на ExitPoint справа от стула; повторные команды во время перехода игнорируются.

Вид сверху (условно, север — направление -Z):

```text
                             ┌──────────────┐
                             │    щиток    │
┌──────────┬─────────────────┤              │
│ санузел  │      ПК         │    общий     │
│          ┆                 │   коридор    │
│          │                 ┆              │
└──────────┤ шкаф            │              │
           ├─────────┆───────┤              │
           │   спальня      │              │
           └────────────────┤              │
                            └──────────────┘
```

## Границы сцены для команды

- `scenes/main.tscn`: сборка компонентов. `scripts/main.gd`: состояния и переходы.
- `scenes/apartment/apartment.tscn`: обычная сохранённая геометрия и свет, доступные в редакторе.
- `scenes/player/player.tscn` + `scripts/player/player.gd`: контроллер персонажа.
- `scenes/terminal/terminal.tscn`: стол/монитор/стул и маркеры SeatView, MonitorView, ExitPoint.
- `scenes/ui/terminal_ui.tscn`: самостоятельный полноэкранный интерфейс, без SubViewport.
- `scenes/ui/hud.tscn`: прицел и подсказки, не перехватывает клики.

На коллайдерах стола/монитора metadata `interaction = &"computer"`.
ExitPoint должен оставаться в свободном месте на полу, минимум в 0.25 м от препятствий.
Стены и предметы используют collision layer 1, игрок — капсулу радиусом 0.25 м.
Маркеры терминала должны оставаться дочерними для корректного переноса стола целиком.

`tools/apartment_layout.gd` — исходник одноразового блокинга;
`tools/bake_apartment.gd` позволяет явно пересобрать `.tscn`.
**Не запускать после ручных правок без намерения заменить их:** инструмент перезаписывает
геометрию квартиры. Для обычной работы художника он не нужен и при запуске игры не выполняется.

## Автоматический desktop smoke test

Godot 4.6.2 standard, совместимые шаблоны. Подставить свой путь к Godot вместо `godot`:

```powershell
godot --headless --editor --path . --import
godot --path . --script res://tests/prototype_smoke.gd
```

Вторая команда требует настоящего окна, временно захватывает мышь и завершается сама.
Не переключать фокус во время теста. У headless DisplayServer нет настоящего pointer lock,
поэтому полный input-тест намеренно отказывается запускаться с `--headless`.

Проверяются: пол и свободное место в каждой зоне, проходы реальной капсулой, блокирование
стенами, скорость шага/бега, остановка при свободной мыши, raycast компьютера,
10 циклов входа/выхода (Esc и сигнал кнопки), защита от повторного ввода,
возврат камеры/управления, безопасная точка выхода и обработчик потери фокуса.
Успех: `PROTOTYPE SMOKE: PASS (0 failures)`, exit code 0.

Необязательные скриншоты комнаты, коридора и рабочего стола:

```powershell
godot --path . --script res://tests/prototype_smoke.gd -- --capture --capture-dir=C:/existing/folder
```

Без `--capture-dir` снимки сохраняются в `user://`. Тест не заменяет проверку ощущения
от управления человеком. Ввод движения в desktop-тесте синтетический; проверка кнопки
через сигнал дополнена реальным кликом в браузерной проверке.

## Ручная приёмка

1. F5 → ЛКМ, пройти все зоны. Проверить масштаб, высоту камеры, скорость и читаемость света.
2. Обойти стул, ванну, кровать, шкаф; попробовать пройти сквозь стены и край коридора.
3. Подойти к монитору, навестись, E → проверить плавность посадки и полный экран ПК.
4. Выйти кнопкой, затем повторить с Esc. Спам E/Esc не должен создавать второй переход.
5. Повторить вход/выход 10 раз, в том числе с разных сторон стола.
6. Alt+Tab в комнате и во время перехода: движение прекращается, после возврата нужен ЛКМ.
7. Изменить окно до 640×360 и обратно: UI и кнопка выхода остаются доступны.
8. Для Web экспортировать `Web`, обслужить `build/web` по HTTP и повторить в Chrome/Firefox.
   После Esc подождать подсказку о возможности захвата и кликнуть. При быстром выходе
   из ПК камера вернётся, но мышь захватывается следующим разрешённым кликом.
