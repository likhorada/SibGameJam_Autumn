# RELAY — чат заказчика (прототип)

## Ручная проверка

1. F5 → «Играть» → сесть за ПК. При первом входе автоматически открывается RELAY.
2. Дождись сообщений заказчика, выбери ответ мышью.
3. Набирай любые буквы: каждая физическая клавиша раскрывает до двух символов
   **выбранного текста**, а не введённую букву. Автоповтор удерживаемой клавиши
   не набирает текст. После полного набора **Enter** отправляет ответ.
4. Пройди три этапа начального диалога. Внутри есть инструкции по CCTV,
   Блокноту, выходу из ПК и ремонту щитка.
5. Для отчёта удерживай **F7 пять секунд** → **«Начать тестовый отчёт»**.
   Нужно включённое питание; команда работает при ходьбе или за ПК.
   Если стоишь, камера сначала переводит тебя к ПК. Не работает у щитка.
6. Ответь на три вопроса тем же способом: выбор → набор → Enter.
7. **3/3 — успех**, любое другое число — провал / «План Б».
   После последней реплики заказчика забег замораживается. Можно начать новый
   или вернуться в главное меню. Переиграть отчёт в той же сессии нельзя.

Тестовые ответы: **Виктор / кофе / Анна**. Эти факты явно помечены как тестовые
и даны в переписке, в том числе при прямом запуске отчёта из dev-панели.
Сейчас это **не проверка наблюдений с CCTV**. Интеграция с настоящей временной
линией и финалом игрового дня ещё не реализована. Фраза о задержке в офисе —
плейсхолдер диалога, не новая механика воздействия на цель.

## Окно, фокус и сохранение

- RELAY открывается также двойным кликом по иконке, через «Пуск» и панель задач.
- Чат — обычное окно игрового рабочего стола: перемещение, размер, сворачивание.
- Входящие сообщения появляются с паузой 0.65 секунды. Доставка приостановлена,
  если чат закрыт/свёрнут, неактивен, открыт «Пуск», dev-панель или игрок не за ПК.
- История, очередь, выбранный ответ и недопечатанная строка живут в текущем забеге.
  Закрытие окна, выход из ПК и отключение электричества их не сбрасывают.
- Esc сохраняет обычный выход из ПК. Ctrl/Alt/Meta-сочетания не печатают реплику.
  Копирование/вставка не позволяют обойти набор выбранного ответа.
- При смене языка история переводится, набранная часть выбранного ответа
  сбрасывается, чтобы прежняя длина не позволяла отправить недописанный перевод.

## Звуки

`scripts/ui/desktop/desktop_input_audio.gd` слушает физические нажатия только
в открытом игровом ПК. Работает во всех приложениях. Случайно выбирает
`assets/audio/keystroke1–9.wav` или `mouse_click1–2.wav`, шина **SFX**, -12 dB.
ЛКМ/ПКМ/средняя кнопка звучат на нажатии, прокрутка — нет.
Отпускания, автоповтор, F7 и Esc не озвучиваются. Входящие сообщения и раскрытие
двух символов за одно нажатие не создают дополнительных звуков.
До шести коротких звуков могут перекрываться. Выход из ПК, dev-панель и итог
останавливают звук. В Web первый реальный клик разблокирует звук браузера;
громкость регулируется существующими настройками SFX/Master.

## Где менять

- `data/chat/contract.gd`: порядок сообщений, варианты ответов, вопросы,
  стабильные ID вопросов и ключи правильных ответов. Без UI-кода.
- `data/translations/ui.csv`: русские и английские тексты `CHAT_*`.
- `scripts/chat/chat_session.gd`: состояние диалога/опроса и подсчёт результата.
- `scenes/ui/desktop/chat.tscn`, `scripts/ui/desktop/chat_app.gd`: представление.
- `scripts/ui/desktop/terminal_desktop.gd`: регистрация приложения и первый вход.
- `scripts/main.gd`: итоговый экран, завершение забега и новый запуск.
- `assets/fonts/static/Handjet-SemiBold.ttf`: шрифт художника из `assets/fonts`
  (Handjet, поддерживает кириллицу). Используется в RELAY и на итоговом экране.
  Предоставленные файлы шрифтов не редактировались.

## Автоматические проверки

```
godot --headless --editor --path . --import
godot --headless --path . --script res://tests/chat_smoke.gd
godot --path . --script res://tests/chat_smoke.gd
```

Для Web — временная копия проекта: main scene = `tests/chat_fixture.tscn`,
удалить `tests/*` из исключений Web preset, экспортировать release в
`build/chat-web/index.html`, затем `node tools/chat_web_check.mjs`.
Можно указать `CHAT_WEB_ROOT`. Production не содержит тестового JS-моста.
Fixture сразу сажает за настоящий ПК; harness выбирает ответы мышью,
печатает физические клавиши, открывает F7 и проверяет оба результата.
Артефакты: `%LOCALAPPDATA%/Temp/opencode/chat_native.png`, `chat_web_*.png`.

### Проверено локально

- Godot 4.6.2 Compatibility: импорт без ошибок; chat smoke headless/native — PASS.
  Проверены оба счёта, неполный Enter, фокус, сохранение черновика при отключении,
  запрет звука вне ПК/dev-панели, итог, реальный новый забег и возврат в меню.
- Регрессии: desktop/power/CCTV smoke headless и prototype smoke native — PASS.
- Dedicated release Web export в Chrome: реальные клики выбора, печать клавиш,
  Enter, число звуковых триггеров, F7-команда, RU/EN, 3/3 и 2/3 — PASS без ошибок
  консоли. Скриншоты чата и обоих итогов просмотрены; размер 640×360 проверен.
- Обычный production Web export и существующий CCTV browser harness — PASS.
- Из-за смены шрифта была найдена ошибка вне чата: `scripts/main.gd` использовал
  `Input.release_pressed_events()`, не привязанный к GDScript в Godot 4.6
  (появится в 4.7+), из-за чего скрипт падал при парсинге в свежих копиях.
  Заменено на `_drop_stale_key_state()` (`Input.flush_buffered_events()` +
  `action_release` по игровым действиям) во всех четырёх местах.
- Firefox и слабое железо не проверены. Автоматические проверки подтверждают
  запуск аудиоплееров и количество триггеров, но не субъективную громкость/тембр.
- Проверки на текущем рабочем дереве: прежние локальные изменения темы/сцены
  сохранены. Они не редактировались ради чата; новые шрифтовые импорты создаёт Godot.
