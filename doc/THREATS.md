# Угрозы — общая архитектура, сосед и полиция

Подключены **PsychNeighbor**, **PoliceRaid** и **PowerOutage** с существом
в коридоре (**CorridorEntity**), интерактивная дверь, укрытия под кроватью/в шкафу
и `night.txt` на игровом рабочем столе. Клавиша **F** переключает фонарик.
Приёмка: [PSYCH_NEIGHBOR.md](PSYCH_NEIGHBOR.md), [POLICE_RAID.md](POLICE_RAID.md),
[CORRIDOR_ENTITY.md](CORRIDOR_ENTITY.md).
Заметка описывает общую архитектуру; детали каждого обработчика — в её доках.
Тестовые probe-события существуют только в `tests/`, исключённых из обычных экспортов.

## Что уже работает

- `Main/ThreatManager`: один слот события, состояния
  **Idle → Warning → Active → Resolved → Idle**. Resolved тоже удерживает слот,
  чтобы новое событие не перекрывало уход и финальные звуки предыдущего.
- Выбираются только зарегистрированные, включённые и доступные обработчики.
  Отсутствующий враг не заменяется невидимым «событием» и не расходует слот.
- Начальная защита, безопасный интервал после завершения, случайная задержка,
  один бросок вероятности на подходящую задержку, взвешенный выбор события.
- Нет догоняющей очереди нападений после длинного кадра или блокировки.
- Сложность сокращает задержки выбора, не длительность предупреждения.
- Отмена обработчика при отключении, остановке забега и выгрузке сцены.
  Ограниченные по времени события имеют watchdog; значение 0 оставляет событие
  ждать явного завершения (отключение света — до настоящего ремонта).
- Перезапуск игры создаёт новый менеджер и чистое состояние. Runtime-переключатели
  отдельных угроз не изменяют общий ресурс настроек.

## Настройки

`data/threats/default.tres` (`ThreatConfig`):

| Параметр | Значение |
| --- | --- |
| Opening Safe Seconds | 45 секунд от начала забега |
| Safe Seconds | 20 секунд после завершения события |
| Min / Max Interval | 25–45 секунд **после** защиты |
| Event Chance | 1.0 на попытку выбора |
| Ramp Seconds | 180 секунд подходящего времени выбора |
| Final Interval Scale | 0.65 |

Подходящее время выбора идёт только после защиты, в ROUTE и без внешних блокировок.
До ALARM.sh, между маршрутами и во время финального отчёта случайный выбор запрещён.
Само активное событие продолжает жить независимо от разрешения случайного выбора.

`ThreatProfile` хранит ID, enabled, относительный вес и длительности фаз.
Зарегистрированы `psych_neighbor`, `police_raid`, `power_outage`.
Сосед использует 5 секунд предупреждения, полиция — 12 секунд.
У отключения Warning/Max Active/Resolved = 0: свет гаснет сразу, watchdog
выключен (чекбокс ждёт настоящего ремонта), слот освобождается сразу после ремонта.
Также доступен `clear_cooldown()` для dev-панели («Разрешить угрозы прямо сейчас»).

## Контракт обработчика

`scripts/threats/threat_event.gd` — Node с методами:

- `can_start()` — можно ли начать событие в текущем мире;
- `can_schedule()` — ворвутся ли случайный выбор сейчас (у отключения — только за ПК);
- `warning_started()`, `active_started()` — вход в фазу;
- `advance(delta)` — обновление текущей фазы;
- сигнал `resolved(outcome)` — переход к завершению;
- `resolved_started(outcome)` — уход/завершающая фаза;
- `ended(outcome)` — обязательная идемпотентная очистка, в том числе при отмене
  во время предупреждения, watchdog и выгрузке сцены.

Обработчик регистрируется один раз через `register_event(id, event)` и становится
дочерним узлом менеджера. Базовый ThreatEvent сам по себе недоступен для запуска.

`request_event(id, true)` — принудительный тест: пропускает стартовую защиту,
задержку и разрешение случайного выбора, **но не** другой активный слот, внешние
блокировки, отключённую угрозу или её `can_start()`.
`set_event_enabled(id, false)` также отменяет уже запущенный обработчик этого ID.
Случайный выбор вызывает `request_event(id)` без форса и учитывает ещё и
`can_schedule()`: отключение выбирается только сидя за ПК.

`Main.disable_threats()` — безопасная команда отключения: отменяет обработчик,
запрещает новые события и возвращает питание, даже если свет был выбит вручную.
В F7 доступны `TriggerNeighbor`, `TriggerPolice`, `TriggerPowerOutage`,
переключатели PsychNeighbor / PoliceRaid / PowerOutage / CorridorEntity,
«Разрешить угрозы прямо сейчас», `DisableThreats` и статус состояния. Панель можно
открыть, не выходя из укрытия. Переключатель `Debug HUD` оставляет на экране
фазы соседа, полиции и существа, а во время активного окна показывает таймер,
дистанцию, запас ошибки, погоню и попадание опасного луча. Production не содержит
тестовых заглушек.

## Связь с существующим сценарием

Атмосферные события принадлежат отдельному `AtmosphereDirector`, не врагам.
Если маршрут заканчивается во время угрозы, отключения или нестабильного контекста,
ShiftDirector ждёт в `WAITING_EVENT`; игрок сохраняет управление для спасения и ремонта.
Атмосфера и угрозы не накладываются: активный атмосферный ивент задерживает новые
угрозы, но никогда не прерывает уже начатую. Укрытие и ПК не закрываются принудительно.
Старая пятисекундная заглушка удалена; при пустом пуле маршрут продолжается сразу.
Контракт и dev-инструменты: [ATMOSPHERE_EVENTS.md](ATMOSPHERE_EVENTS.md).

Существующий `ApartmentPower` больше **не генерирует отключения сам**: его прежний
cooldown/chance-генератор удалён, осталась только логика света и фонарика.
Кнопка «Отключить питание», случайный выбор и вызов силы через `trigger_outage()`
все идут через один канал `threats.request_event(&"power_outage", true)`.
Реальное отключение устанавливает блокировку `blackout` на время отсутствия
питания, а ремонт (четыре рубильника или `restore_power()`) резолвит адаптер.
Сцена встречи существа живёт внутри обработчика отключения: см. CORRIDOR_ENTITY.md.

Финальный отчёт ждёт завершения активного события; после конца маршрута новый
случайный выбор и прежние случайные отключения выключены. Тестовый forced API
остаётся намеренным обходом обычного расписания.

## Проверки

```
godot --headless --editor --path . --import
godot --headless --path . --script res://tests/threat_smoke.gd
godot --path . --script res://tests/threat_smoke.gd
godot --headless --path . --script res://tests/outage_smoke.gd
godot --path . --script res://tests/outage_smoke.gd
```

Общие проверки живут в `tests/threat_checks.gd`: фазы, запрет перекрытий,
стартовая защита/безопасный интервал, шанс 0, доступность и переключатели,
watchdog, отсутствие watchdog у отключения, поздний сигнал, синхронное завершение
из callback, сложность, очистка, реальное питание/пугачка/отчёт и новый забег.
Отключение и существо покрыты `tests/outage_checks.gd` (см. CORRIDOR_ENTITY.md).

Web: во **временной копии** с нужным main scene (`tests/threat_fixture.tscn` или
`tests/outage_fixture.tscn`), убрать `tests/*` из исключений Web preset,
импортировать и экспортировать release. Тестовый JS-результат отсутствует в production.

```powershell
$env:THREAT_WEB_ROOT = '<каталог экспорта>'
$env:THREAT_WEB = '1'
node tools/chat_web_check.mjs
```

Godot 4.6.2 Compatibility: threat/outage smoke headless+native и общие проверки
в Chrome WebGL2 release — PASS. Регрессии shift/power/chat/desktop/CCTV/menu/
neighbor/ambience/flashlight/camera_motion — PASS. Input-фикстуры Web
(RU/EN: сосед, полиция, отключение) и сквозной shift harness (3/3 и 2/3) — PASS.
В части headless-прогонов остаются известные предупреждения о двух WAV playback
при выходе; нативные прогоны и Chrome завершились без этих ошибок.
Firefox, слабое железо и баланс реальных врагов пока не проверены.
