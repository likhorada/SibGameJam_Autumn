# Вопросы на ПК и фигура в санузле

Два случайных ивента, которые оставляют объект после завершения **мгновенного запуска**.
Они не занимают слот ThreatManager/AtmosphereDirector, пока игрок их не заметит.
`AtmosphereResidents` — run-local владелец оставшихся объектов и колоды вопросов.

## Окно с вопросом (`question_popup`)

- Только случайный запуск **за ПК**, после ALARM.sh. Не резервируется на переходы.
- Один из 12 вопросов пользователя, с равным шансом и **без повторов текста за забег**.
  Ключи отдельно в `data/atmosphere/questions.gd`, тексты RU/EN в `data/translations/ui.csv`.
- Немодальное, неподвижное до перетаскивания, без звука/мигания и без ввода ответа.
  Заголовок позволяет перетащить окно, крестик — убрать. Нет сворачивания без способа
  вернуть окно. Приложения вокруг продолжают работать; клавиатурный фокус не крадётся.
- Нет автоисчезновения. Выход/возврат за ПК сохраняет окно. Одновременно только одно.
- При старте FIREWALL BREACH вопрос убирается, независимо от будущего результата взлома.
- Профиль `repeatable=true` разрешает повторный запуск **типа** события, но не повтор
  уже выбранного текста. Открытое окно и пустая колода исключают его из выбора даже в dev.
- Каждый новый вопрос расходует обычную квоту случайных событий. Общие интервалы,
  лимиты и запрет догоняющих запусков не изменены; колода из 12 не означает 12 окон за забег.

## Фигура (`bathroom_apparition`)

- Только случайный запуск, **за ПК и при ходьбе**, обычно один раз за забег.
- Точка/направление: `Apartment/BathroomApparitionPoint` в сцене квартиры. Фигура стоит
  в проходе санузла лицом к выходу, не внутри сантехники.
- Отдельный визуальный экземпляр существующей сущности, с локальным тёмным материалом
  и фиксированной позой. Нет AI, коллизий, урона, погони, тревожного proximity-эффекта
  или поворота головы за игроком. Материалы и поведение настоящих врагов не изменяются.
- Нельзя поставить фигуру в уже видимую точку, даже dev-командой. Если это место
  вне фрустума — достаточно текущей геометрической проверки. Для появления за стеной
  используется кэш прямой видимости из physics; изменившаяся камера/размер/маркер
  не могут воспользоваться устаревшей проверкой.
- Ждёт без таймера до взгляда. Несколько точек головы/тела проверяются по полному
  фрустуму камеры, включая периферию, и лучом до них через физику квартиры.
  Видимость через стену не засчитывается; центрировать прицел не требуется.
- Удаляется **после первого реально отрисованного видимого кадра**, не до него.
  ПК, dev-меню и неактивное окно не засчитываются как просмотр квартиры.
- При начале Warning любой настоящей угрозы, включая отключение света, фигура
  убирается синхронно, до появления/действий врага. Сама угрозы не блокирует.
- `data/atmosphere/bathroom_settings.tres`: необязательный `loop_sound` и громкость.
  При назначении играет один пространственный источник из санузла, пока фигура стоит.
  **Сейчас файл не назначен: полностью тихо, никаких синтов или звука-заглушки.**

## Очистка и интеграция

Оба объекта убираются перед финальным опросом, при отключении/отмене атмосферы,
захвате игрока, конце забега и выгрузке сцены. Новый забег создаёт свежую колоду.
Простое завершение другого ивента оставшиеся объекты не удаляет.
Обычные угрозы не удаляют вопрос: он скрыт вместе с ПК и может остаться при возврате.

- `scripts/atmosphere/atmosphere_residents.gd`: колода, доступность, владение, очистка.
- `question_popup.gd`: UI на базе существующего DesktopAppWindow.
- `bathroom_apparition.gd`: визуальный объект, лучи в physics, подтверждение post-draw.
- `question_event.gd` / `bathroom_event.gd`: обычные адаптеры AtmosphereEvent. После
  успешной постановки синхронно сообщают `spawned` и освобождают активный слот.
- `AtmosphereDirector.set_event_condition(id, Callable)`: run-local доступность без
  пересоздания обработчиков на каждом кадре. Обычные ивенты по умолчанию одноразовые;
  новый флаг профиля `repeatable` нужен только там, где это явно разрешено.
- Профили/сцены: `data/atmosphere/{question_popup,bathroom_apparition}.tres`,
  `scenes/atmosphere/{question_popup,bathroom_apparition}.tscn`.

## Dev и проверка

F7 → **TriggerQuestionPopup** / **TriggerBathroomApparition**.
Обе команды также доступны через общий селектор ID. В статусе/Debug HUD показаны
оставшаяся колода, открытый вопрос и присутствие фигуры; причины удаления пишутся
в dev-историю. Dev обходит одноразовость, но не открытый вопрос, пустую колоду,
видимую точку появления, угрозу, отключение, опрос или другой активный ивент.

```
godot --headless --path . --script res://tests/residents_smoke.gd
godot --path . --script res://tests/residents_smoke.gd
```

Для Web во временной копии: main `tests/residents_input_fixture.tscn`, включить
`tests/*` в release export и запустить:

```powershell
$env:RESIDENTS_WEB_ROOT = '<каталог экспорта>'
$env:RESIDENTS_WEB = '1'
node tools/chat_web_check.mjs
```

Для общих lifecycle-проверок main = `tests/residents_fixture.tscn`, runner
`THREAT_WEB_ROOT` / `THREAT_WEB=1`. Тестовые команды/позы и ускорение времени не входят
в production. Нативные снимки сохраняются в `%LOCALAPPDATA%/Temp/opencode/`:
`residents_question.png`, `residents_peripheral_figure.png`, `residents_peripheral_empty.png`.

### Проверено (Godot 4.6.2 Compatibility)

Финальные desktop/headless/Web-проверки повторены поверх `37b177c` (AdditionalTextures);
новые текстуры сохранены без изменений.

- `residents_smoke`: headless, настоящее desktop-окно и Chrome/WebGL2 release — PASS.
  Все 12 переводимых вопросов без повторов, drag/крестик, отсутствие таймера,
  повторяемая выборка в общей квоте, занятый/исчерпанный вопрос, очистка взломом;
  появление за ПК, удержание вне взгляда, стена, реальная периферия кадра,
  запрет видимого появления, очистка угрозой, опрос, disable, новый забег и live teardown.
- Для штатного пустого `loop_sound` проверено отсутствие источника. Отдельно в тесте
  назначен существующий click-файл: проверены один пространственный источник,
  повтор и очистка. Production-настройки звука не изменены, синтез не используется.
- Chrome input fixture: RU/EN, реальные F7/dev-кнопки, drag/крестик/повтор вопроса,
  клавиатура приложения под ним, ресайз, реальный post-draw периферийной фигуры,
  окклюзия стеной, запрет видимого спавна, угроза и финальный отчёт — PASS.
- Headless-регрессии: atmosphere, idiot, firewall, shift, threat, police, neighbor,
  outage, fairness, lifecycle, chat, desktop, power — PASS. В части старых тестов
  остаются известные предупреждения об аудиоресурсах при завершении процесса.
- Firefox, слабое железо и субъективная заметность одно-кадрового силуэта не проверены.
