# Первый наблюдательный забег

## Как играть

1. F5 → «Играть» → сесть за ПК → завершить вводную переписку RELAY.
2. После последнего ответа начинается **60 секунд** на осмотр и взлом.
   В CCTV / ОФИС / DESK прочитай четыре цифры на мониторе. Запиши в Блокнот.
3. Открой **ALARM.sh** двойным кликом или через «Пуск», нажми кнопку запуска.
   До завершения инструктажа кнопка заблокирована. Звука сирены пока нет.
   Просрочка завершает забег с «Планом Б».
4. Цель в охристой куртке встаёт из кресла и покидает офис (18,5 секунды после тревоги).
   Межсценовая точка атмосферного события; ПК не закрывается. За ПК доступны
   [You Are An Idiot](YOU_ARE_AN_IDIOT.md) и [FIREWALL BREACH](FIREWALL_BREACH.md). Если кандидатов нет, следующий
   маршрут начинается сразу, точка фиксируется только в dev-панели.
5. Магазин использует готовую сцену `shop.tscn`. Цель подходит к алкогольной полке,
   берёт одну бутылку, несёт её к КСО, ставит на левый лоток, ждёт и уходит.
   Весь маршрут — 62 секунды. Выбирается **вино, джин или водка**, случайно на забег.
   Камера ПОЛКА показывает выбранную бутылку, КАССА — её выкладку; подписи читаются
   и на чёрно-белом изображении. Это те же художественные модели, что на витрине.
6. Ещё одна межсценовая точка → улица. Через 12 секунд цель достигает
   слепой развилки и выбирает случайно переулок, аллею или парк.
   Проверяй камеры веток: там есть другие прохожие. Полный маршрут — 56 секунд.
7. После улицы HUD просит вернуться к ПК. При посадке с питанием автоматически
   открывается RELAY с вопросами: код (3 варианта), купленный алкоголь (3), направление (3).
   Только **3/3** даёт победу. Угаданные ответы принимаются, просмотр не отслеживается.

До взлома случайные отключения заблокированы. После запуска разрешается обычная
система питания с её существующим cooldown. Таймлайн не останавливается при
отключении света, выходе из ПК, открытии Блокнота или dev-панели.
Межсценовое событие ждёт завершения активной угрозы, восстановления питания
и устойчивого контекста (ходьба / ПК); не прерывает ремонт и не вытаскивает из укрытия.
Во время ожидания следующий маршрут не начинается. На время атмосферного события
и ожидания перехода новые угрозы и отключения заблокированы.
Если улица закончилась без питания, отчёт ждёт восстановления и входа в ПК.
Отчёт также ждёт завершения уже начатой угрозы. После улицы новые случайные
угрозы и отключения больше не запускаются; ручные dev-команды остаются тестовыми.
Новый забег создаёт новые факты, чистую переписку и таймер.

## Где менять

- `scenes/cctv/observation_shift.tscn`: список сцен этапов смены в инспекторе.
- `scenes/cctv/locations/office.tscn`, `shop.tscn`, `street.tscn`:
  окружение, цель, маршрутные точки и камеры редактируются в Godot. Подробнее:
  [CCTV_SCENES.md](CCTV_SCENES.md).
- `data/observation/shift.gd`: идентификаторы ответов для напитков и направлений.
- `scripts/observation/shift_director.gd`: состояния INTRO → DEADLINE → ROUTE →
  WAITING_EVENT (если нужно) → EVENT → ROUTE … → REPORT → ENDED;
  выбор фактов, срок, отчёт, переходы.
- `scripts/cctv/observation_location.gd`: общий интерфейс сцены, чтение маршрутных
  Marker3D и маркеров выходов. Логика особых событий — в скриптах конкретных сцен.
- `CCTVSystem.replace_location()`: освобождает предыдущую локацию и обновляет
  каталог камер в **одном** существующем SubViewport.
- `ChatSession.questions`: вопросы текущего отчёта; `live_report` исключает
  выдачу старых тестовых ответов. Старый dev-опрос сохранён отдельно.
- `data/translations/ui.csv`: новые ключи `OBS_*`, RU/EN.

F7 → **DEV: завершить маршрут / событие** ускоряет проверку.
Отдельная старая команда тестового отчёта отключает сценарный прогресс этого забега.
`observation_shift_enabled=false` в main позволяет тестировать прежние CCTV-сцены
изолированно (используется только старым smoke-тестом камер).

## Атмосферные события

Заглушка удалена. `AtmosphereDirector` поддерживает случайные и межсценовые события,
На переходах доступны You Are An Idiot и FIREWALL BREACH; отдельно случайно появляются
[вопросы и фигура в санузле](RESIDENT_EVENTS.md). Точка перехода — `_finish_stage()`; его продолжение
ждёт завершения события. Подробнее: [ATMOSPHERE_EVENTS.md](ATMOSPHERE_EVENTS.md).

## Проверки

`godot --path . --script res://tests/shift_smoke.gd` — сквозной native-прогон:
таймер, запуск, смена камер, покупка без питания, прерывание щитка, улица,
финальный отчёт с реальными фактами, победа и просрочка. Скриншоты:
`%LOCALAPPDATA%/Temp/opencode/shift_{office,shelf,checkout,street}.png`.

Web: в отдельной копии main scene = `tests/shift_fixture.tscn`, убрать `tests/*`
из исключений экспорта. Выполнить release Web export, затем:

```
$env:CHAT_WEB_ROOT = '<папка экспорта>'
$env:SHIFT_WEB = '1'
node tools/chat_web_check.mjs
```

Chrome/WebGL2: PASS — реальный клик запуска сигнализации, смена сцен,
ввод ответов с клавиатуры, RU/EN, 3/3 и 2/3. Таймлайн в browser fixture ускоряется
тестовыми командами, production их не содержит. Native shift smoke — PASS.
Регрессии chat/desktop/menu/power/CCTV — PASS. В headless при быстром выходе
встречаются прежние предупреждения о двух WAV playback амбиента (см. AMBIENCE.md).
Модели и скелетные анимации CCTV подключены; отдельная звуковая сирена пока не добавлена.

### Проверка трёх покупок

`godot --path . --script res://tests/shop_purchase_smoke.gd` проверяет все три выбора:
путь до конкретной бутылки, достижение её кистью, перенос с сохранением масштаба,
выкладку на маркер лотка и оценку правильных/неправильных ответов. Native сохраняет
`%LOCALAPPDATA%/Temp/opencode/shop_{0,1,2}_{shelf,held,carry,checkout}.png`.
Для Web-фикстуры из [CCTV_GUYRIG.md](CCTV_GUYRIG.md) запустить
`node tools/cctv_animation_web_check.mjs <export-directory> --shop`.

Проверено после перехода на `shop.tscn` (Godot 4.6.2 Compatibility):
- Native: `shop_purchase_smoke`, `shift_smoke`, `cctv_smoke`, `menu_smoke` — PASS,
  последние прогоны завершились без ошибок. Скриншоты полки/кассы просмотрены.
- Release Web в Chrome: `SHOP PURCHASE WEB: PASS (wine, gin, vodka)` — все три
  реальные бутылки, перенос, выкладка и совпадение с ответами отчёта. Скриншоты
  `%LOCALAPPDATA%/Temp/opencode/cctv_animation_web_shop_*.png` просмотрены.
- Headless: проверки покупки/смены/меню дошли до PASS, но в отдельных прогонах
  Godot затем падал при завершении (signal 11); это не считается чистым PASS процесса.
  В Web остаётся прежнее предупреждение UID у `room_camera_feed.tscn`; новых ошибок нет.
