# Электричество, щиток и dev-меню

## Проверить быстро

1. F5 → «Играть». **Удерживай F7 полные 5 секунд**.
2. В dev-панели нажми **TriggerPowerOutage**, затем «Назад» / Esc.
   Свет гаснет мгновенно, из комнаты выбрасывает, фонарик включён.
3. Нажми ЛКМ для захвата мыши, открой дверь в общий коридор через **E**
   (теперь она изначально закрыта), пройди к щитку в конце коридора
   (координаты щитка примерно `4.2, 1.45, -6.82`). Светит только слабый фонарик.
   Клавиша **F** гасит/зажигает фонарик и в коридоре, и у щитка.
4. В коридоре во время отключения появляется фигура (см. CORRIDOR_ENTITY.md):
   стоять тихо и без света — риск минимальный.
5. Наведи прицел на корпус щитка → **E**. Камера приближается, курсор свободен.
6. Наведи на ручку и удерживай ЛКМ **3.5 секунды**. Ручка движется вверх:
   **курсор нужно вести за ней**. Если увести курсор или отпустить ЛКМ — возврат
   вниз со скоростью полного хода за **1.2 секунды**.
7. Полностью поднятый рубильник фиксируется ON. Порядок произвольный, один за раз.
8. **Esc или WASD** позволяют отойти. Зафиксированные остаются, недотянутые падают.
9. После четырёх ON свет включается, фонарик гаснет, камера возвращается к игроку.
   При необходимости нажми ЛКМ для захвата мыши. ПК снова работает.

Для короткого ручного теста без пробежки можно открыть `tests/power_fixture.tscn`
через F6: это настоящая квартира со стартом у щитка, автоматические отключения
в этой **тестовой сцене** выключены. В обычный экспорт `tests/*` не входит.

## Случай отключения и питание

- Случайных «кубиков» у электричества больше нет. Отключение выбирается общим
  планировщиком ThreatManager (`power_outage`-обработчик) **только пока игрок сидит
  за ПК**: стартовая защита забега, межугрозовый интервал и веса единые
  (см. THREATS.md). Принудительная кнопка / `trigger_outage()` работает в любом
  режиме, но подчиняется занятому слоту и переключателям угроз.
- Пока питание выключено, новые отключения не происходят; новые четыре OFF
  выставляются только при переходе ON → OFF. Самовосстановления нет.
- При отключении выключаются Light3D квартиры, затемняется ambient и экран ПК,
  автоматически включается фонарик со следованием за текущей камерой:
  основной мягкий конус и широкий ближний засвет. Ближний конус слегка направлен
  вниз, подхватывает пол и предметы перед игроком, затухает на 3 м. Расширение
  ближней засветки не расширяет опасную область существа. Оба источника с тенями;
  объёмного тумана нет.
- **F — фонарик** в ходьбе (при захваченной мыши) и на крупном плане щитка.
  За ПК F печатает букву в чате/заметках — светом не мигает. При включённом свете
  клавиша игнорируется. Чёрный экран: подсказка
  «F — фонарик» видна без наведённой интеракции.
- Существо в коридоре во время отключения и его правила — в CORRIDOR_ENTITY.md.
- Если игрок за ПК / садится / встаёт, переход прерывается, игрок переносится
  на существующую безопасную ExitPoint. Приложения и заметки сохраняются.
  ПК недоступен до ремонта. CCTV viewport отключён, но жизнь локаций не останавливается.
- В крупном плане ходьба отключена. Потеря фокуса, отпускание ЛКМ, уход курсора,
  выход и dev-панель прерывают удержание. Уход курсора не переносит удержание
  на соседний рубильник: для нового захвата нужно отпустить и снова нажать ЛКМ.
- На Esc в Web не запрашивается pointer lock: браузер может запретить его в этом
  же событии. После выхода достаточно ЛКМ с учётом существующей паузы браузера.

## Inspector

**`scenes/main.tscn` → PowerSystem** (`scripts/power/power_system.gd`):

| Свойство | По умолчанию |
| --- | --- |
| `Flashlight Energy / Range / Angle` | 0.9 / 3.5 м / 35° |
| `Flashlight Spill Energy / Range / Angle` | 0.48 / 3.0 м / 82°; широкий ближний засвет |
| `Blackout Ambient Energy` | 0.012 |
| `Outage Sound / Restore Sound` | пустые AudioStream-слоты |
| `Behind Sounds` | массив необязательных AudioStream |
| `Behind Chance` | 0.5 на попытку звука |
| `Behind Min / Max Interval` | 5 / 13 сек |
| `Behind Distance` | 1.8 м позади камеры |

Момент отключения больше не настраивается здесь — только общий планировщик
угроз (`data/threats/default.tres`), а поведение существа —
`data/threats/corridor_entity.tres`.

**`scenes/power/fusebox.tscn` → Breakers** (`scripts/power/fusebox.gd`):
`Raise Seconds = 3.5`, `Fall Seconds = 1.2`, `Raise Sound`, `Fall Sound`, `Latch Sound`.
Сцена встроена дочерним узлом в существующий `Apartment/Fusebox`.
**CloseView** — обычный Marker3D для крупного плана, редактируется без кода.
**Handles** содержит четыре экземпляра `lever.tscn`: геометрия заменяется в этой сцене.
`PickBody` должен оставаться на collision layer 2, это отдельная маска для курсора.
Номера ручек назначаются автоматически по порядку в Handles; нужно ровно четыре.

## Звук

Звуковых файлов в проекте нет — все слоты честно пустые, ничего не проигрывается.
Перетащи свои `.ogg` / `.wav` в соответствующие AudioStream-поля Inspector.
Подъём воспроизводится/повторяется, пока ручка поднимается; отмена останавливает
его и запускает возврат; фиксация — отдельный щелчок. Шина механики — SFX.
Не используй loop-файлы для одноразовых щелчков, возврата и включения.

Случайные шорохи работают только во время мини-игры: после случайной паузы
бросается шанс, выбирается непустой клип, источник ставится позади камеры.
Одновременно играет не более одного клипа, шина Ambience, громкость -16 dB.
При выходе, dev-панели и потере фокуса шорох прекращается, а на время активной
встречи существа шорохи молчат (шаги важнее). Это не враг и не ИИ.
Настрой расстояние и громкость дочерних MotionAudio / ClickAudio для механики.

## Dev-панель

Только внутри квартиры, не в меню. F7 удерживается **5 секунд подряд**;
раннее отпускание или потеря фокуса сбрасывают отсчёт. Во время перехода камеры
открытие ждёт стабильного режима. Мир и таймеры **не на паузе**.

- **Бесконечная выносливость**: заполнить запас, снять истощение и усталость,
  отключить расход. При выключении обычный расход возобновляется с полного запаса.
- **TriggerPowerOutage**: принудительное отключение через общий планировщик угроз
  (из любого режима, но не поверх активной угрозы/пугачки).
- **Восстановить питание (без ремонта)**: тестовый обход четырёх рубильников.
- **Dev: разрешить угрозы прямо сейчас**: обнуляет ожидание планировщика; это не
  гарантирует событие (выбор всё ещё зависит от режима, слота и включённости).
- Статус: питание, ожидание следующей угрозы, флаги фиксации, состояние Threats
  (`state / active_id`) и закрытость комнатной двери.

**`Main/DevMenu → Enabled = Off`** полностью отключает панель перед публикацией.
По умолчанию она работает и в release/Web. Это намеренно доступный инструмент
для команды, не античит. Настройки dev не сохраняются между игровыми сессиями.

## Проверки

```
godot --headless --editor --path . --import
godot --headless --path . --script res://tests/power_smoke.gd
godot --path . --script res://tests/power_smoke.gd
godot --headless --path . --script res://tests/outage_smoke.gd
godot --path . --script res://tests/outage_smoke.gd
```

Power smoke проверяет принудительное отключение через планировщик, выключение
света/ambient, F-переключения фонарика, запрет ПК, скорости ручек, сохранение ON,
ремонт, отключение в трёх состояниях ПК, заметки, луч взаимодействия, крупный
план, выход, F7 и unlimited stamina. Отключение и существо — в `tests/outage_checks.gd`
(см. CORRIDOR_ENTITY.md).

Для браузерного теста — временная копия проекта: main scene заменить на
`res://tests/power_fixture.tscn`, в Web preset временно убрать `tests/*` из исключений,
экспортировать в `build/power-web/index.html`. Затем `node tools/power_web_check.mjs`.
`POWER_WEB_ROOT` позволяет указать другой каталог. В production JS-моста нет.
Harness использует реальный F7, мышь и движущиеся 3D-ручки; тестовый JS-мост
даёт только телеметрию и команду входа в ПК для отдельной проверки отключения.

Скриншоты: `%LOCALAPPDATA%/Temp/opencode/power_web_*.png`.

### Проверено локально

- Godot 4.6.2 Compatibility: импорт; power smoke headless/native — PASS
  (принудительное отключение через планировщик, фонарик и ремонт без cooldown).
- Отключение/существо: outage smoke headless/native — PASS, общие regression
  (threat/shift/chat/neighbor/desktop/ambience/menu/CCTV/stamina/camera_motion/
  prototype native/police) — PASS.
- Production Web export, обычный Chrome/local HTTP: menu и CCTV harness — PASS,
  включая fullscreen, переход в квартиру, управление ПК и захват мыши.
- Dedicated Web fixture: реальные 5 секунд F7, dev-команды, поднятие четырёх
  движущихся ручек мышью, возврат при отпускании/уходе, выход по Esc и WASD,
  сохранение фиксации, ремонт, гашение фонарика и отключение за ПК — PASS.
  Без ошибок консоли. Снимки крупного плана и dev-панели просмотрены.
- Пока не проверены Firefox, слабое железо и субъективная слышимость/баланс
  звука щитка. Рандом отключения покрыт планировщиком угроз в outage/threat
  логических тестах, а не длительным статистическим прогоном.
- Проверки проведены на текущем рабочем дереве с сохранёнными локальными
  правками сцены/темы; чистая копия только коммитируемых изменений не собиралась.
- Правка фонарика: мягкий основной конус и широкий ближний засвет. Native
  `tests/flashlight_smoke.gd` проверяет реальные пиксели: ближние боковые поверхности
  светлеют, поверхность за пределами дальности не меняется; power smoke — PASS.
  Dedicated Chrome fixture повторно экспортирован и прошёл весь power harness.
